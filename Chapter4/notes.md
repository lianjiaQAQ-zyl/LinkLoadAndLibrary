## 第四章 静态链接
### 4.1 空间与地址分配
1. 多个目标文件链接称为可执行文件时，一般将相同性质的段合并到一起。
2. **装载是把可执行文件中的程序代码和数据映射到进程的虚拟地址空间，为程序运行做准备**，通常发生在程序启动时。
3. 连接器一般都采用一种叫两步链接（Two-pass Linking）的方法：
	- **空间与地址分配**扫描所有的输入目标文件，获取它们各个段的长度、属性和位置，并且将输入目标文件中的符号表中所有的符号定义和符号引用收集起来，放在一个全局符号表。这一步以后，链接器可以获得所有输入目标文件的段长度，并将它们合并，计算输出文件中各个段合并的长度和位置，建立映射关系。
	- **符号解析和重定位：** 读取输入文件中段的数据、重定位信息，进行符号解析和重定位，调整代码中的地址。
4. `ld` 链接器默认的程序入口为 `_start`
5. `VMA` 即 `vitrul memory address`，表示虚拟地址；`LMA` 表示 `Load Memory Address`，表示加载地址，正常情况下两个值一样。
6. 在 linux 系统下， 32 位 x86，传统非 PIE 程序 ELF 文件的虚拟地址从 `0x 0804 8000` 开始分配；64 位 x86，传统非 PIE 程序 ELF 文件的虚拟地址从 `0x 0040 0000` 开始分配；PIE 程序指的是 Position Independent Executable，即位置无关可执行文件，这里的位置指的是操作系统装载的虚拟地址。
7. 连接器在完成地址和空间分配之后就可以**确定所有符号的虚拟地址。**

### 4.2 符号解析与重定位

1. 近址相对位移调用指令：用“目标函数距离下一条指令有多远”来表示调用目标的 `call` 指令。
2. `objdump -r` 命令可以查看目标文件中的重定位表：
	- 偏移：表示该入口在要被重定位的段中的位置，值是重定位入口所要修正的位置的第一个字节相对于段起始的偏移。
	- 类型：每一种处理器的指令格式不一样，所以重定位所修正的指令地址格式也不一样。
3. 当链接器扫描完所有的输入目标文件之后，所有未定义的符号都应该能够在全局符号表中找到，否则链接器就报符号未定义错误。
4. 重定位类型：
	- 绝对寻址修正：将地址修改为 **符号的实际地址 + 保存在被修正位置的值**
	- 相对寻址修正：将地址修改为 **符号的实际地址 + 保存在被修正位置的值 - 被修正的位置**

### 4.3 COMMON 块

1. 早期的 `Fortran` 没有动态分配空间的机制，程序员必须事先声明他所需要的临时使用空间的大小，`Fortran` 把这种空间叫 `COMMON` 块，当不同的目标文件需要的 `COMMON` 块大小不一致的时候，以最大的那一块为准。
2.  直接导致 COMMON 机制的原因是编译器和链接器允许不同类型的弱符号存在，**但是最本质的原因还是链接器不支持符号类型，无法判断各个符号的类型是否一致。**

### 4.4 C++ 相关问题

1. 因为模版、外部内联函数（具有外部链接属性的 inline 函数）、虚函数表等机制的存在，C++ 编译器在很多时候都会在不同的编译单元里生成相同的代码。为了消除重复代码，一个有效的做法是将每个模版的实例代码都单独的存放在一个段里，每个段里只包含一个模版实例，这样链接器链接的时候就可以消除重复代码。
2. C++ 允许同一个 `inline` 函数在不同编译单元中重复定义，但这些定义必须满足一致性要求。
3. C++ 全局对象的构造函数在 main 之前执行，析构函数在 main 之后被执行。因此 ELF 中定义了：
	- .init：进程的初始化代码。
	- .fini：进程终止代码指令。
