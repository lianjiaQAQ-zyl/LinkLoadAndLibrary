# 第三章 目标文件里有什么
## 3.1 目标文件的格式

1. ELF 文件格式：PIE 表示位置无关可执行文件。

| 类型     | ELF 类型标记  | 基本含义              |
| ------ | --------- | ----------------- |
| 可重定位文件 | `ET_REL`  | 供链接器进一步链接         |
| 可执行文件  | `ET_EXEC` | 可执行程序的一种文件类型      |
| 共享目标文件 | `ET_DYN`  | 共享库，也用于 PIE 可执行文件 |
| 核心转储文件 | `ET_CORE` | 保存进程状态，供调试分析      |
2. 使用 `file` 命令查看文件格式。

## 3.2 目标文件是什么样的

1. 目标文件将代码、数据等信息按照不同的属性，以 **节（section）** 的形式进行存储，有时候也叫做**段（segment）**。
2. 程序源代码编译后的机器指令经常放在 **代码段（Code Section）** 中，一般命名为 `.code` 或者 `.text` ，全局变量和局部静态变量数据经常放在 **数据段（Data Section）**，一般命名为 `.data`。
3. 未初始化的全局变量和局部静态变量放在 `.bss` 段，这是因为它们的默认值都是 0，放在 `.data` 段浪费空间。所以存放在 `.bss` 段中，利用 ELF 节头信息记录大小总和即可，相当于预留位置，并没有内容，也不在文件中占用空间。
4. 
   ```
		# 查看各节大小
		objdump -h elf_example.o
		
		# 查看变量属于哪个节
		objdump -t elf_example.o
		
		# 查看 .data 的实际字节
		objdump -s --section=.data elf_example.o
		
		# 尝试查看 .bss 的实际字节
		objdump -s --section=.bss elf_example.o
   ```

### 3.4 ELF 文件结构描述

1. ELF 文件中的段表（Section Header Table）：描述了所有段的信息，比如段名、段的长度、在文件中的偏移、读写权限等。段表在 ELF 文件中的位置由 ELF 文件头的 "e_shoff" 成员决定。
2. `e_entry`（Entry point address）：规定 ELF 程序的入口虚拟地址，操作系统在加载完该程序后从这个地址开始执行进程的指令。
3. 段名是一个字符串，位于 `.shstrtab` 的字符串表，而因为字符串长度不一致，所以为了保证段表中的每个元素大小是相通的，只在结构体中存放当前段名在 `.shstrtab` 中的偏移，即 `sh_name`.
4. 段的类型相关常量以 `SHT_` 开头（Section Header Type）；段的标志位（Section Header Flag, SHF）表示该段在进程虚拟地址空间中的属性。
5. 符号表中每一行就是一个符号，数组元素，与段表类似，为了让每个元素大小一样，存偏移而不是真实名称，真实字符串名称在 **字符串表**。
|对比|符号表|字符串表|
|---|---|---|
|保存内容|符号的名称偏移、值、大小、类型、所属节等|名称等文本|
|组织方式|固定大小的记录数组|一串字节，字符串以 `\0` 结尾|
|如何查找|按条目索引访问|按字节偏移访问|
|是否保存变量的实际数据|不保存|不保存|
6. 对于每一个需要重定位的代码段或者数据段，都会有一个相应的重定位表，比如 `.text` 段的重定位表就在 `.rel.text` 段中。
7. 只要分析 ELF 文件头，就可以得到**段表和段表字符串表**的位置，从而解析整个 ELF 文件。

### 3.5 链接的接口 —— 符号

1. 在链接中，目标文件之间相互拼合实际上是目标文件之间对地址的引用，即对函数和变量的地址的引用。在链接的过程中，将函数和变量统称为符号，函数名或变量名就是符号名。
2. 每一个目标文件都会有一个对应的符号表，里面记录了所有的符号，每个定义的符号都有一个对应的值，称为符号值，对于变量和函数而言，符号值就是它们的地址。
3. 符号表类型分类：
	- 定义在目标文件中的全局符号，可以被其他目标文件**引用**。
	- 在本目标文件中引用的全局符号，但是没有在本目标文件中进行定义，称为**外部符号**。
	- 段名，由编译器产生，**值就是该段的起始地址**。
	- 只在编译单元内部可见的局部符号。（链接过程忽略）
	- 行号信息。
4. 可以使用 `nm` 命令查看目标文件的符号。
5. ELF 文件中的符号表往往是文件中的一个段，段名为 `.symtab`。
6. 可以使用 `c++filt` 来解析符号修饰以后的名称。
7. C++ 编译器会将在 `extern "C" ` 修饰的代码当作 C 语言代码处理，不进行符号修饰。
