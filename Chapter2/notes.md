# 第二章 编译和链接
### 2.1 被隐藏了的过程
1. 预编译 -> 编译 -> 汇编 -> 链接。（以 `gcc hello.c` 为例）
	- 预编译：使用预编译器 `cpp` 生成 `.i` 文件。预编译过程中将`#define` 删除，展开宏定义；处理所有的条件预编译指令，比如`#include` `#if` ；删除注释；添加行号和文件标识；保留编译器指令，如 `#pragma` 
	- 编译：将预处理好的文件进行词法分析、语法分析、语义分析以及优化后生成相应的汇编代码文件。
	- 汇编：将汇编代码转变为机器可以执行的指令。
	- 链接：将不同的目标文件组合起来，生成最终的可执行文件。

2. `hello.i` 中  `#` 开头的行叫**行标记**（line markers），是预处理器给编译器的位置信息。然后是文件路径，最后是标记位，1 表示进入一个被包含的文件，2 表示从一个被包含的文件返回包含它的文件，3 表示来自系统头文件，4 表示告诉 C++ 编译器按 C 语言链接规则处理相关声明，便于调用 C 库函数。

3. 对于 `.o` 文件（可重定位目标文件），可以使用 `objdump` 进行查看。`-r` 选项可以查看重定位信息。

### 2.2 编译器做了什么
1. 编译器编译过程：扫描，语法分析，语义分析，源代码优化，代码生成和目标代码优化。
2. 扫描（`lex`）：源代码程序被输入到 `Scanner` ，进行词法分析，利用类似于有限状态机的算法将源代码的字符分割为一系列的 `token`，一般可以分为以下几类：
	- 关键字
	- 标识符
	- 字面量，包含数字、字符串
	- 特殊符号，如运算符 
3. 语法分析（`yacc`）：对 `token` 进行语法分析，产生语法树，整个分析过程采用上下文无关语法，生成的语法树就是以表达式为节点的树。
4. 语义分析：编译器能分析的语义是**静态语义**，即在编译期就可以确定的语义。比如给语法树中的节点标注类型。
5. 中间代码生成：很难直接在语法树中进行优化，所以一般是将整个语法树转化为**中间代码**，比如三地址码和 P-代码。同时根绝中间代码将编译器分为前端和后端：
	- 前端：产生机器无关的中间代码
	- 后端：将中间代码转换成目标机器代码
### 2.3 连接器年龄比编译器长
1. 重定位（Relocation）：重新计算各个目标的地址过程。
2. 程序被分割为多种模块以后，需要有一种机制将不同模块进行组合，也就是模块间进行通信，比如模块间的函数调用、变量访问，即模块之间**符号**的引用问题。链接就是解决这个问题。
### 2.4 模块拼装——静态链接
1. 从原理上讲，链接过程就是**把一些指令对其他符号地址的引用加以修正**。主要过程包含：
	- 地址和空间分配（Address and Storage）
	- 符号决议（Symbol Resolution）
	- 重定位（Relocation）
2. 静态链接：A 模块中引用了 B 模块中的变量或函数（符号），编译器在编译 A 模块的时候，并没有该符号的相关地址，所以将其暂时搁置 ，然后由连接器根据符号去查找对应的地址，将 A 模块目标文件中的对于该符号的调用指令修改为该符号真正的地址。
3. 地址修正的过程被叫做**重定位**，每个要修正的地方叫**重定位入口（Relocation Entry）**。
### 补充
1. ARM64 汇编：
	- 每条 ARM64 指令占 4 字节
	- `int` 类型的返回值放在 `w0`
	- `<ltmp0>` 是编译器／汇编器生成的局部临时符号。

| 记号           | 含义                                       |
| ------------ | ---------------------------------------- |
| `x0`～`x30`   | 64 位通用寄存器                                |
| `w0`～`w30`   | 对应 `x` 寄存器的低 32 位，例如 `w8` 是 `x8` 的低 32 位 |
| `sp`         | 栈指针，保存当前栈顶地址                             |
| `wzr`        | 32 位零寄存器，读取它总是得到 `0`                     |
| `#0x10`      | 立即数，即直接写在指令里的常数；`0x10` 是十进制 `16`         |
| `[x9]`       | 访问 `x9` 保存的地址所指向的内存                      |
| `[sp, #0xc]` | 访问地址为 `sp + 12` 的内存                      |
2. ```
relocation.o: file format mach-o arm64
Disassembly of section __TEXT,__text:
0000000000000000 <ltmp0>:
       0: d10043ff     sub sp, sp, #0x10
       4: 52800000     mov w0, #0x0                ; =0
       8: b9000fff     str wzr, [sp, #0xc]
       c: 90000009     adrp x9, 0x0 <ltmp0>
      10: f9400129     ldr x9, [x9]
      14: 52800208     mov w8, #0x10               ; =16
      18: b9000128     str w8, [x9]
      1c: 910043ff     add sp, sp, #0x10
      20: d65f03c0     ret
   ```
   此处 `adrp x9, 0x0 <ltmp0>` 是在找 got 表，0x0 是当前指令所在页与 got 表所在页的偏移，因为还没有链接，所以显示为 0x0，`ldr x9, [x9]` 相当于 `ldr x9, [x9, 0x0]`，是找到 got 表以后，根据偏移找到引用的外部变量，因为没有链接，所以偏移量还是 0
   链接以后汇编如下：
   ```
relocation: file format mach-o arm64
Disassembly of section __TEXT,__text:
00000001000003c0 <_main>:
	1000003c0: d10043ff    sub sp, sp, #0x10
	1000003c4: 52800000    mov w0, #0x0                ; =0
	1000003c8: b9000fff    str wzr, [sp, #0xc]
	1000003cc: 90000029    adrp x9, 0x100004000 <_var>
	1000003d0: 91000129    add x9, x9, #0x0
	1000003d4: 52800208    mov w8, #0x10               ; =16
	1000003d8: b9000128    str w8, [x9]
	1000003dc: 910043ff    add sp, sp, #0x10
	1000003e0: d65f03c0    ret
   ```
   这里链接器进行了优化，不再经过 got 表拿到表项，即将 `ldr` 指令优化为 `add` 指令，所以 `0x100004000` 这里就是 var 变量所在的页的起始地址。
